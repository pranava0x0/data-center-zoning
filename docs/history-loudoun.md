# Loudoun County: application and permit history

As of November 15, 2026 (Eastern time), the county's public GIS services returned **536 land-use case files, 1,373 files from its issued-permit table, and 24 from its submitted-permit table** whose configured fields explicitly mention a data center or an equivalent term. Only **39** of the issued files have **both** type `Building (Commercial)` **and** work class `New Construction`. Neither 39 nor 1,373 counts unique operating facilities. The archive contains all matches to the documented filter in the three source tables, not every permit ever issued for a data center.

The 536 plan files include 269 engineering plans, 50 special exceptions, 22 zoning map amendments, and other records such as correspondence, premeetings, and bond releases. The service reports 381 Approved, 144 In Review, 7 Submitted, 2 Submitted - Online, and 2 Denied. Their plotted date is the **application date**, including for approved and denied cases: the layer does not publish decision dates. A zoning action, proposed subdivision, or engineering approval does not establish a building permit, energization, or commencement of operations. Titles and descriptions can also refer to a neighboring facility, road, or associated infrastructure.

All 1,373 matched files in the separate issued register have source status `Issued`; 1,370 have an observed issue date. The 261 commercial building files break down into 172 tenant fit-ups, 44 alterations, 39 new construction, four miscellaneous structures, one addition and one demolition. Other permit types include 344 commercial electrical, 318 commercial zoning, 178 commercial fire protection, 29 land disturbance and 14 VESMP. Zoning and fire permits are independently countable permit files but do not establish construction of a new facility. The 24 submitted-register files (22 Submitted - Online, 2 Invoiced and Paid - Same Day) have **no issuance inferred**. No file number is shared across the three result sets in this snapshot. ## What the machine actually searched

The [configuration](../data/history/virginia/loudoun_county/building_and_zoning_gis/config.json) and [snapshot manifest](../data/history/virginia/loudoun_county/building_and_zoning_gis/manifest.json) contain all fields, SQL predicates, local patterns, dates and pull URLs. There is **no lower date bound**, status shortlist, permit-type shortlist or current-approval restriction. The script issues case-insensitive SQL `LIKE` queries against plan **name or description** and permit **description**. The seven coarse terms look for ordered fragments associated with data center/centre, “data ctr,” data hall, server farm, and colocation facilities. It then requires one of four case-insensitive whole-phrase regexes in an individual field; it does not join text across fields. It accepts selected spacing, hyphenation, plurals, “data processing center” and “datacenter.” Seven plan rows and 14 issued-permit rows failed the phrase check. Empty text is not evidence; codes, addresses, operator names and cloud-campus aliases alone do not qualify. The project label for permits is a shortened description; full matched description and fields are retained.

Records dated after the configured calendar cutoff are excluded. Missing dates are retained as unknown, never imputed from the latest status or a second event. Epoch timestamps use America/New_York, as the services specify Eastern with daylight saving. A retrieval timestamp is in the manifest. LandMARC's per-row snapshot dates, application dates and final dates, when reported, are separately labeled in the output. Status is a snapshot, not a reconstructed sequence of status changes; querying a later snapshot with a past cutoff would not reconstruct what was known on that past day.

Within each source, rows sharing a file number are grouped, falling back to a source GUID when a number is absent. All contributing object IDs, GUIDs, parcel PINs (where available), matched fields, and any conflicting dates/statuses are kept; conflicting primary dates are not silently resolved. Twenty-five issued files produced multiple matching rows (190 surplus rows). This key resolves parcel rows **within a filing**, not campus identities or related phases. Separate reviews or permits for one campus remain distinct. Each file links to an official record-number query that can be reopened, and its archived rows can be found by object ID.

## What the public layers miss

A useful independent check is the county's [FY 2022 **adopted** budget, Volume 1](https://www.loudoun.gov/DocumentCenter/View/166015/FY-2022-Adopted-Budget---Volume-One): its discussion of 2020 reports approximately **3 million square feet of new data center space permitted**. Our issued-register screen finds **no** commercial building new-construction file dated 2020. The discrepancy demonstrates historical undercoverage; it does not establish which files were missing or why. Rising annual text matches cannot be used to infer growth in facility construction without independent coverage controls.

The county also maintains [monthly issued-building-permit reports](https://www.loudoun.gov/1164/Issued-Building-Permit-Reports) with archived PDFs dating to 2015. Its current reporting system offers both half-month and complete-month files; counting both would duplicate permits. The [public archive](https://www.loudoun.gov/DocumentCenter/Index/3506) loads its file list in a JavaScript interface, and its full folder-list route is behind a path disallowed by the site’s robots rules. The supplemental pass below uses directly indexed, publicly downloadable report URLs; the full monthly archive has not been enumerated. The [nonresidential pipeline](https://www.loudoun.gov/6094/Non-Residential-Development-Pipeline) separately classifies development by land use; its [FY 2025 permit map](https://lfportal.loudoun.gov/LFPortalinternet/0/edoc/1970366/FY25%20New%20Non-Residential%20Building%20Permits%20Map.pdf) shows 68 new nonresidential permits across **all** mapped uses and is not 68 data-center permits. These are alternate evidence paths for files with opaque descriptions. The [county EPD dictionary](https://logis.loudoun.gov/photos/EPD/EPD_Data_Dictionary.pdf) also combines built and permitted structures in one development-status class; it is not an operating-facility register.

## Supplemental recovery: classified structures and numbered monthly records

The [Existing Structures layer](https://logis.loudoun.gov/gis/rest/services/Projects/BuildOut_LandUse/MapServer/0) directly identifies 223 distinct local GIS structure IDs whose main or secondary use code is exactly `COM_DATA_CENTER`. All 223 observed records had this as their primary use; 217 have building-permit issue dates from September 1997 through 2025, six have no issue date. Twenty-two structure records have 2020 issue dates. The [data dictionary](https://logis.loudoun.gov/photos/EPD/EPD_Data_Dictionary.pdf) and [county mapping-tool documentation](https://www.loudoun.gov/3905/Existing-Potential-Development-Tool-EPD) explain the broader “Existing or Permitted” status. These are not 223 confirmed permit file numbers or 223 operating facilities. The layer exposes a parcel PIN, GIS structure ID and a date; it exposes **no building permit number**. The source version date is **July 1, 2025 for all 223 rows**; this is not a November 2026 inventory of existing buildings.

The [crosswalk](../data/history/virginia/loudoun_county/monthly_reports/epd_crosswalk.json) searched the **entire issued-permit table on those parcels**, without requiring a data-center word in the description; it then required exact parcel PIN, local issue date, commercial building permit type and New Construction work class. There were **11 structures with one candidate number**, **three with multiple candidates** and **209 with none**. Each candidate is a real issued-register number, not a proven match to that structure; even a single candidate is held as a lead, not promoted as a second permit. None of the 22 2020 structure records yielded a numbered candidate. Two have the same parcel/day (August 24); converting the rows into a permit count would double-count that key without establishing how many files were issued.

For 2020, **July, August, September and December** each have three dated structures; January, June and November have two each; February, March, April and May have one each. This ranks months to retrieve from the [county archive](https://www.loudoun.gov/DocumentCenter/Index/3506), not the number of permits missing. For example, [structure 1472](https://logis.loudoun.gov/gis/rest/services/Projects/BuildOut_LandUse/MapServer/0/query?where=OBJECTID%3D1472&outFields=OBJECTID%2CLU_USE%2CLU_BP_ISSUE_DATE%2CLU_MCPI&f=pjson&returnGeometry=false) records May 18, 2020. Scope note: the [other county GIS layer covering permit history back to 2010](https://logis.loudoun.gov/gis/rest/services/Projects/ResBuildingPermits/MapServer/1) describes residential permits, so it cannot fill this commercial history.

**Sixteen sampled county reports** spanning 2015–2019 and 2024–2025 provided 1,522 pages and 11,437 parsed source rows. The screen recovered **120 distinct numbered commercial-building files**: 36 already in the GIS description screen and **84 additions** (78 modern plus six legacy). Of the 84 additional rows, seven are labeled New Construction and five legacy rows NEWCO; 80 are marked issued by source status or legacy issued-log heading, one is Finaled and three are In Review. The archive holds 11,632,276 bytes of official monthly PDFs.

Derived records in [history/virginia/loudoun_county/monthly_reports.json](../output/history/virginia/loudoun_county/monthly_reports.json) keep non-file structure observations in their own dataset. New numbered report rows go in a separate dataset and are suppressed if their permit number already appears in the primary issued-table result. [The per-month audit](../data/history/virginia/loudoun_county/monthly_reports/counts.json) retains every matched number and the overlap. Newer PDF reports qualify an actual commercial building file by the **Structure Type** column exactly equaling Data Center or a data-center phrase in its own **Permit Description**. A reference to a different file inside that description does not become another issued file. Older reports use a different schema: only a commercial occupancy code and an explicit phrase in the main **Purpose** cell qualify; work classes such as `NEWCO` remain in county wording. This conservative parser can miss wrapped purpose text and opaque campus names. Owner, applicant, mailing address and contractor names are not matched. The full date, number and PDF page remain available for inspection.

The legacy parser recovered six numbered commercial permits absent from the issued-table screen: one in October 2015, one in December 2016, three in November 2018 and one in April 2019. Five carry the original construction-type code `NEWCO`; one is `ADD`. For example, the [April 2019 log](https://www.loudoun.gov/DocumentCenter/View/151069/Issued-Building-Permit-Report-April-1-30-2019) identifies B80293260200, April 11, as an addition to a data center.

Three of the additional modern files carry a printed issue date but status **In Review** (BLDC-2024-003556, -007687 and -007689). The PDF and source wording are retained; treat these as discrepant report entries pending county confirmation of issuance.

This is a bounded monthly reconciliation, not a complete census of report months. Only complete-month files with directly located official URLs are included. For one legacy report, the URL says June 2019 but the printed report heading identifies May 2019; the printed reporting period controls. The modern January 2025 file is labeled 1–31 in its URL but its header ends January 30; its actual rows determine the extracted dates, and coverage of the 31st is **not established**. The county says it has archived reports from 2015; uncaptured months are **unknown**, never zero.

## Replay and adapt

From the project directory, run:

```sh
python3 scripts/collectors/virginia/loudoun_county/building_and_zoning_gis.py           # verify pinned bytes and rebuild offline
python3 scripts/collectors/virginia/loudoun_county/building_and_zoning_gis.py --fetch   # capture a new live snapshot and rebuild
python3 scripts/collectors/virginia/loudoun_county/monthly_reports.py  # offline EPD/parcel crosswalk and report rebuild
python3 scripts/collectors/virginia/loudoun_county/monthly_reports.py --fetch  # fresh ArcGIS and PDF captures
```

The capture enumerates every candidate object ID before requesting attributes in batches of at most 125, below the service return limits. It fails on service errors, schema drift, partial/duplicate batches or an inconsistent ID set. Each batch, layer schema, ID enumeration and total-row count is persisted as its original JSON bytes under `cache/history/loudoun/`, with byte length, SHA-256 and provenance URL in the manifest. Offline replay verifies these hashes and the exact configuration hash, reconciles the complete ID sets, and asserts unique output IDs. Source state can change between pulls; preserve the configuration and manifest alongside the cache to retain an old snapshot before refreshing. The fetcher uses the project's robots policy and delay. It deliberately does not request geometry, staff contact fields or mailing addresses.

To adapt to another public ArcGIS service, copy the configuration, change the jurisdiction/ID prefix, output paths, layer endpoints, field mappings and terms, then pass `--config PATH --fetch`. Validate the layer's timezone, field definitions and event semantics against its documentation first. The extra evidence fields are currently mapped for the Loudoun schemas; extend that mapping if the new service uses other names. A list of distinct registered file IDs proves full enumeration **for the query**, not complete identification of data-center activity or every historical regulatory regime.
