# Refreshing and validating one jurisdiction

Every state, DC and territory with permit history has one command to check it and one to refresh it:

```sh
python3 scripts/pipeline/jurisdiction.py list            # jurisdictions, collectors, series, live flags
make check-TX                                   # offline replay twice, network blocked; byte-compare
make refresh-TX                                 # live pull, re-check, row diff in output/refresh/TX.json
make check-all                                  # every jurisdiction; writes output/jurisdiction_checks.json
```

The mapping lives in [data/jurisdiction_registry.json](../data/jurisdiction_registry.json). It is generated by
`jurisdiction.py trace`, which runs every collector in `make history` order and records which
`output/history/<collector path>` files each one writes; [history/series.csv](../data/history/series.csv) assigns each
series to a jurisdiction and gives its `path` under `output/` (resolved in code by `series_path()`). Hand edits go in `overrides` (a collector's live flag) and `prerequisites` (shared inputs).

## What `check` proves

1. Each collector for the jurisdiction runs with `HTTP(S)_PROXY` pointed at a closed port, so any attempt to reach
   a publisher fails. Passing means the series rebuilds from cached, hash-pinned bytes alone.
2. It runs twice. Both runs must produce byte-identical series files (determinism).
3. The result is compared with the published edition. A difference is reported as drift (code or cache changed).
4. Each series must be a non-empty list with the interchange fields `build_history.py` requires, unique IDs,
   ISO dates, and only rows for its own jurisdiction.
5. `history_materialization.py --strict` re-hashes every archived evidence file the receipts cite.

It does not prove completeness or that a portal still says the same thing. Only `refresh` contacts publishers.

## What `refresh` does

1. Runs shared prerequisites the jurisdiction depends on (today: the EPA ICIS-NPDES national archive, split per state).
2. Sets `ATLAS_REFETCH=1` so collectors re-pull sources they already archived (`--gap-fill-only` only fetches
   missing ones), then runs each of the jurisdiction's own collectors with its live flag (`--refresh` or `--fetch`, normalized by the
   registry). National collectors (FAA, Corps, EPA water, councils) are skipped unless `--include-national`,
   because they rewrite every state they cover.
3. Runs `check`. If it fails, or any live step failed, `data/` and `output/` are restored from a stash taken before the
   run, and the new cache bytes are left for review.
4. Writes `output/refresh/<JUR>.json`: each step's exit code and time, then added, removed and changed row IDs.
5. Nothing is republished until `make build` runs the full gate (COMPASS checks, tests, browser UAT).

Collectors whose inputs were captured by hand (no live mode) are listed as skipped, not silently treated as fresh.

## Current status (November 16, 2026)

- `check --all`: 55 of 55 jurisdictions pass. All 80 collectors in `make history` rebuilt with the network blocked,
  produced byte-identical output on two runs, and matched the published edition. One published metadata file
  (`data/history/new_mexico/coverage.json`) was stale (12 archived sources listed; the manifest has 17). The replay corrected it.
- `refresh CT`: a live pull of Connecticut's sources finished in 16 seconds with no row changes.
- Collectors without a live mode (inputs pinned by hand): `history_ms.py` (MDEQ enSearch pages), `history_la.py`
  (local case files; quarterlies and EPA come from prerequisites), `history_manassas_city.py`, `history_guref.py`, and
  the national EPA water derivations, which refresh through the `epa_icis` prerequisite.
- Gaps recorded in the registry: the Northern Mariana Islands has no history series; Delaware, Maine, Rhode Island and
  Missouri have only shared national or multi-state collectors.
