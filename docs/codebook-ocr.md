# Recovering local ordinance evidence from scanned codebooks

The national PDF scanner found **562 government-referred URLs** with zero pages containing more than 80 embedded text characters. Deduplicating by SHA-256 yielded **557 PDFs / 18,155 physical pages**, including one zero-page file. This describes the existing scanner corpus, not every zoning code in the United States. A small amount of embedded text does not mean an image-only page is blank. The published project snapshot is **November 15, 2026**; visual review and packaging occurred November 16.

We OCRed **363 pages from 57 distinct documents in 36 states** and found candidate terminology in **54 pages in eight documents**. After reading rendered government pages and checking adoption, six documents support **17 data-center provisions**; the other two were not applicable evidence. The 207 stored snippets are bounded keyword contexts (up to five per page), not separate laws.

|Scope | Result |
|---|---:|
|Entire documents submitted to OCR |24|
|Partial documents, with exact checked page numbers |33|
|Distinct PDFs not selected |500|
|Total physical pages in sampled PDFs |2,237|
|Unread physical pages in sampled PDFs |1,874|
|OCR pages with ≥80 recognized characters |348|
|OCR pages with shorter or blank results |15|

No row means “no ordinance.” OCR can miss text, tables, marginal notes and unusual terminology. A complete OCR attempt is not a complete legal review; a referral can be an older edition, an unadopted proposal or a consultant contract. The sample is deliberately enriched, so its hit rate cannot estimate nationwide prevalence.

## Sampling and OCR

1. The scanner's source population, government referrals, Census issuer matches, source ranks and hashes are frozen in `cache/codebook-ocr/population.json.gz`. Original PDF bytes already exist in `cache/codebooks/files/<SHA-256>.pdf`. A repeated URL or filename is not an independent source. We did not fetch replacement copies or send pages to an external OCR service.
2. First select all six explicit data-center referrals, then rotate states for 18 long zoning books (≥40 pages), 18 compact zoning instruments (3–8 pages, entire), and 15 medium-length books (9–39 pages). Rank by available state priority, market markers, year in referral, and a stable hash tie-break. One jurisdiction per broad cohort where possible; exclude Missouri. All selected documents had zero matched market markers; this set is not a census of major markets. Complete compact instruments and priority titles receive more attention than scattered pages in large codes. Titles can mislead in both directions.
3. The fixed plan at `cache/codebook-ocr/cohort.json` reserves initial probes and at most two follow-up pages per partial document. Seed the front matter and bookmark headings matching definitions, use tables, industrial districts and development standards. An OCRed table-of-contents label or nearby hit can select later pages. Printed numbers, physical page indexes and chapter numbers need not align. When no navigation cue works, fixed spread pages provide fallbacks. Store the actual one-based physical pages rather than implying a whole chapter was covered.
4. macOS Vision in accurate mode supplied 355 pages. Eight pages of North Centre’s scan timed out in Vision and were processed using English Tesseract 5.5.3 with tesserocr 2.12.0 and a pinned fast language model (180 dpi). Each page keeps the engine/version, OCR lines and SHA-256 of UTF-8 lines joined by newline; changing an engine can change characters and page follow-ups. `scripts/lib/ocr_vision.swift` is the project-local Vision helper. Each worker is an isolated process; the default cap is three and the maximum is four. OCR is for discovery; a claim must cite the visually checked original.
5. The review manifest is keyed by rule ID. Each row pins the source SHA-256, physical page, review image hash, OCR text hash, reviewer, date and method. This is agent visual review, not independent human legal signoff. The staging step preserves the original native PDF text (even if blank) in the source store, so an OCR result cannot silently pass a native-text test.

## Reproduce or extend

Run commands from the project root. `python3 scripts/ordinances/codebooks/ocr.py --verify` works offline with the checked-in/local originals and evidence cache. It rebuilds the inventory and staged provisions and verifies all **57 selected original hashes**, every recognized page and page number, untouched page accounting, jurisdiction/URL matches and all 17 stored visual judgments. `codebook_ocr_validation.json` records the resulting artifact hashes. It does not authenticate unsampled originals beyond the digests recorded by the upstream scanner.

```sh
python3 scripts/ordinances/codebooks/ocr.py --verify
# Run only missing pages in this frozen cohort. OCR engine is used only on cache misses.
python3 scripts/ordinances/codebooks/ocr.py --ocr --engine vision --workers 2 --verify
# Portable alternative: tesseract with English language data on PATH
python3 scripts/ordinances/codebooks/ocr.py --ocr --engine tesseract --workers 2 --verify
```

The Python package `pymupdf` is required. Vision requires macOS and Swift; the Linux/Windows Tesseract binary or an isolated tesserocr/Pillow environment is also supported. For the exact fallback used here: install `tesserocr==2.12.0` to `cache/codebook-ocr/runtime` and download [English tessdata_fast](https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/eng.traineddata) to `cache/codebook-ocr/tessdata/eng.traineddata`; the expected SHA-256 is `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`. Then choose `--engine tesserocr`. Engine versions and the actual text are retained in the page archive for portability. To recreate or expand the selection, use a **separate project copy or archive the entire existing OCR cache and output artifacts first**. The initial `--docs` and `--page-budget` caps only apply when creating a new plan; reruns honor the published frozen plan. Timeouts become errors/incomplete coverage and can be retried; no negative record is generated.

Files under `data/national/`: `codebook_ocr_inventory.csv` (all 557 originals, referrals, places, checked pages, unread counts); `codebook_ocr_pages.jsonl.gz` (full page-level text and hashes); `codebook_ocr_hits.json` (search contexts); `codebook_ocr_summary.json`; `codebook_ocr_claims.json` (auditable authored source); `codebook_ocr_rules.json` (viewer-ready projection); `codebook_ocr_visual_reviews.json`; `codebook_ocr_validation.json`. The source manifest for ordinary shared ingestion is `cache/codebook-ocr/reviewed_index.json`; native PDF content and normalized native text are staged in `cache/sources`. OCR JSON by original and page, selected source images, engine assets and run details remain in `cache/codebook-ocr/`.

The distinct upstream PDFs occupy 1.413 GB, including 204 MB in the sample. Reusing those bytes, the 363-page compressed text-and-receipts artifact is about **244 KiB**; the full local OCR working cache (including engines, language assets and reviewed images) is about 21 MiB. At this sample's **compressed text bytes per page only**, 18,155 pages would be roughly 12 MiB in addition to originals. Image retention, further originals and further model-backed review are separate costs; sparse or particularly dense pages can materially change that projection. Source counts are measured, not forecasts of how many laws remain.
